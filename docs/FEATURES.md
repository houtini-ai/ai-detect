# ai-detect 2.0.0: feature inventory

A plain, factual list of what the tool does on the `rebuild-2026-11` branch, written for whoever writes the README. Every command output below was produced by running that command on 24 Nov 2026 (Windows 11, Python 3.13, CPU); this file is generated by `scripts/build_features_doc.py` from `docs/features.template.md`, so re-run the script after a code change. Model facts carry their source and read date. Nothing here is published: no PyPI, npm or registry upload has been made.

Related documents: `docs/MODEL-EVAL-2026-11.md` (measurements and which model to pick), `docs/HOW-IT-WORKS.md` (diagrams), `docs/UX-REVIEW-2026-11.md`, `docs/RELEASE.md`, `docs/REVIEW-2026-11.md` (the code review this work started from), `CHANGELOG.md`, `THIRD-PARTY-MODELS.md`.

## 1. What it is

A local AI-text detector. It scores writing with open detector models that run on the user's own machine, per sentence and per document, explains flagged sentences with pattern findings and rewrite suggestions, and reports page-level "structure and style" tells as a separate signal. It has three front ends over one engine: a command-line tool, an MCP server, and a web UI served on 127.0.0.1. MIT licensed. Text, files and fetched pages are never sent anywhere. The only network traffic is: model downloads from Hugging Face, the one page a URL scan is asked to fetch, and (only if the user turns it on and gives an address) a vision endpoint.

## 2. Install, exactly as it works today

Not on PyPI and not on npm (both names checked free on 24 Nov 2026: `https://pypi.org/pypi/ai-detect/json` and `https://registry.npmjs.org/@houtini%2fai-detect` return 404). Install is from a clone.

```bash
git clone https://github.com/houtini-ai/ai-detect
cd ai-detect
pip install .                 # core: torch, transformers, mcp, starlette, uvicorn
pip install ".[light]"        # + onnxruntime: needed by light, gpttrace-150m, gpttrace-1b
pip install ".[web]"          # + playwright: URL input and .html files
playwright install chromium   # once, after the [web] extra
pip install ".[conpara]"      # + sentencepiece, protobuf: the conpara model
pip install ".[all]"          # everything above
```

- **Python 3.11 or later** (`requires-python = ">=3.11"`). Current torch, transformers and onnxruntime need it.
- Extras: `light` (alias `onnx`), `gpu-directml`, `conpara`, `web`, `all`, `dev` (pytest).
- Commands installed: `ai-detect` and `ai-detect-mcp`. `python detect.py ...` still works from the clone.
- `python scripts/check_env.py` prints what is installed.
- What was verified: the package builds and installs from source into a fresh environment through `uv` on Windows and in a clean `python:3.12-slim` Docker container, and the MCP server completes a handshake and a scan there (see `docs/RELEASE.md`). A plain `pip install .` into a new virtual environment was not run separately.
- The note until 2.0.0 is on `main`: the URL above clones the old code. This branch is local only.

## 3. Command line

### Commands and flags

| Command | Does |
|---|---|
| `ai-detect [input] [flags]` | Scan one input and print the report |
| `ai-detect serve [--port N] [--no-browser]` | Run the web UI on 127.0.0.1 (default port 8765, next free port if busy) and open the browser |
| `ai-detect download <id\|id,id\|all>` | Download model weights with a progress bar; resumes if interrupted |
| `ai-detect models [--json]` | List models, size, licence, RAID rank, download state |

| Flag | Short | Meaning |
|---|---|---|
| `--file PATH` | `-f` | A text, Markdown or HTML file. `.html`/`.htm` are rendered with Chromium (needs `[web]`) |
| `--text STRING` | `-t` | Text given on the command line |
| `--url URL` | `-u` | Fetch one page and scan it (needs `[web]`) |
| positional | | A file path, a URL, or text. A value that looks like a path but does not exist is an error |
| (none) | | Reads standard input |
| `--compare A B` | `-c` | Scan two files or URLs and print both reports and the change |
| `--batch LIST` | `-b` | A text file with one path or URL per line (`#` comments allowed); prints a summary table |
| `--model ID[,ID...]` | `-m` | One model, or up to five comma-separated as an ensemble. Default `desklib` |
| `--ensemble` | `-e` | Every downloaded model, up to five |
| `--device auto\|cpu\|cuda` | `-d` | Default `auto`: GPU if available |
| `--perplexity` | `-p` | Add the GPT-2 perplexity and burstiness readout (548 MB on first use) |
| `--no-tells` | | Skip structure and style tells |
| `--low-memory` | | With an ensemble, load and unload models one at a time |
| `--timeout SECONDS` | | URL fetch timeout, default 30 |
| `--export PATH` | `-o` | Also write the report: `.html`, `.csv` or `.json` (with `--batch`: `.csv` or `.json` summary) |
| `--json` | `-j` | Print the full report as JSON |
| `--version` | `-V` | Print the version |

A model that is not on disk is downloaded first, with a progress bar on stderr.

### The JSON report (`--json`, and what the web UI reads)

Top-level keys: `sentences`, `model_ai_pct`, `ai_count`, `human_count`, `skipped_count`, `total`, `model`, `text_metrics`, `pattern_totals` (these nine are unchanged from 1.0.0), plus `models`, `flagged_pattern_totals`, `document_ai_pct`, `passages`, `words`, `blocks`, `operating_point`, `assessment`, `tells`, `perplexity`, `source`, `model_info`, and for an ensemble `per_model` and `ensemble`; for a URL, `page`.

Each sentence: `index`, `block`, `kind`, `sentence`, `label` (`AI`, `Human`, `Skipped`), `confidence`, `ai_prob`, `human_prob`, `diagnostics` (each `pattern`, `match`, `suggestion`, `start`, `end`), `scores` (raw probability per model), `calibrated` (per model), `calibrated_prob`, `flags` (per model), `agreement`, `why`, and `perplexity` when requested.

- With one model, `ai_prob` and `label` are the model's raw probability and the 0.5 cut-off, as in 1.0.0. `calibrated_prob` is the same sentence read at the model's 5%-false-positive operating point.
- With several models, `ai_prob` is the ensemble's calibrated mean and `model` is `"ensemble"`.
- `assessment`: `label` (`Likely AI` over 60, `Likely human` under 40, otherwise `Uncertain`), `ai_pct` (the calibrated document score), `confidence` (`high`, `moderate`, `low`), `notes`, `breakdown` (share of words in sentences reading as AI / uncertain / human).
- Sentences under five words, and all headings, are `Skipped`. Tables and code blocks are not scored.

## 4. MCP server

Start with `ai-detect-mcp` (or `python -m ai_detect.server`). Works with MCP Python SDK 1.x (tested on 1.10.1) and 2.x (the Docker run resolved 2.x). The pin is `mcp>=1.10,<3`.

Server name `ai-detect`. Transport: stdio. The table is read from the running server's `tools/list` answer.

| Tool | Parameters (default) | Read-only | May start a download |
|---|---|---|---|
| `compare_texts` | `text_a`, `text_b`, `model` (`"desklib"`), `device` (`"auto"`) | yes | yes |
| `detect_ai_file` | `path`, `model` (`"desklib"`), `device` (`"auto"`), `include_all_sentences` (`false`), `perplexity` (`false`) | yes | yes |
| `detect_ai_text` | `text`, `model` (`"desklib"`), `device` (`"auto"`), `include_all_sentences` (`false`), `perplexity` (`false`) | yes | yes |
| `detect_ai_url` | `url`, `model` (`"desklib"`), `device` (`"auto"`), `include_all_sentences` (`false`), `perplexity` (`false`), `timeout` (`30.0`) | yes | yes |
| `get_model_status` | `model` (`"desklib"`) | yes | no |
| `list_models` | none | yes | yes |
| `open_dashboard` | `open_browser` (`false`) | no | no |
| `prefetch` | `model` (`"desklib"`) | no | yes (that is its job) |
| `scan_batch` | `items`, `model` (`"desklib"`), `device` (`"auto"`) | yes | yes |

### Tool descriptions (as sent to the client)

**`compare_texts`**

```
Analyse two texts (e.g. a draft and an edit) and report both results and
the change. May trigger a model download: returns status "downloading" at
once if the model is not on disk.
```

**`detect_ai_file`**

```
Score a local file (the engine reads it, so a long draft never enters the
conversation). Text and Markdown are read directly; .html files are rendered
with headless Chromium (needs the [web] extra).

Args:
    path: Absolute path to a UTF-8 .txt, .md or .html file.
    model: A model id or comma-separated ids (ensemble). Default 'desklib'.
    device: 'auto', 'cpu', or 'cuda'.
    include_all_sentences: Also return every scored sentence.
    perplexity: Add the GPT-2 perplexity readout.

May trigger a model download (see detect_ai_text): returns status "downloading"
at once if the model is not on disk.
```

**`detect_ai_text`**

```
Score text for AI authorship, sentence by sentence and as a whole document.

Args:
    text: The text to analyse (plain text or Markdown).
    model: A model id, or up to 5 comma-separated ids to run as an ensemble
        (see list_models). Default 'desklib'.
    device: 'auto' (GPU if available, else CPU), 'cpu', or 'cuda'.
    include_all_sentences: Also return every scored sentence, not just flagged ones.
    perplexity: Add a GPT-2 perplexity and burstiness readout (548 MB on first use).

Returns the mean sentence score and verdict, the document score with a stated
confidence, AI-flagged sentences with pattern diagnostics and rewrite suggestions,
structure-and-style tells (a separate signal), and dashboard_url.

May trigger a model download: if the model is not on disk this returns at once with
status "downloading" and a progress message instead of a result.
```

**`detect_ai_url`**

```
Fetch ONE web page with headless Chromium and score its article text. Also
reports visual-shape tells (card grids of three, gradient hero, and so on) and
saves a screenshot to the dashboard. Fetches only this URL: no crawling, no
form submission, no sign-in. Needs the [web] extra (Playwright).

Args:
    url: An http(s) address.
    model: A model id or comma-separated ids (ensemble). Default 'desklib'.
    device: 'auto', 'cpu', or 'cuda'.
    include_all_sentences: Also return every scored sentence.
    perplexity: Add the GPT-2 perplexity readout.
    timeout: Seconds to wait for the page.

May trigger a model download (see detect_ai_text): returns status "downloading"
at once if the model is not on disk.
```

**`get_model_status`**

```
Is a model ready, downloading, not downloaded or failed?

`status` is 'ready', 'downloading', 'absent' or 'failed' (`state` says the
same with 'not_downloaded' for absent). While downloading it gives bytes_done,
bytes_total, percent and eta_seconds; after a failure, the reason in `error`.
`message` is one sentence to relay. Also returns dashboard_url. Never triggers
a download.
```

**`list_models`**

```
List every detection model: size, licence, RAID leaderboard rank (with its
source and the date it was read), runtime, and download status. Never
triggers a download.
```

**`open_dashboard`**

```
Return the URL of the local web UI (bound to 127.0.0.1), starting it if
needed. It shows scan results with highlighted text, the tells panel,
compare, batch, history and live model download progress. Set
open_browser=true to open it in the user's default browser. Never triggers
a download.
```

**`prefetch`**

```
Start downloading a model's weights from Hugging Face in the background so
the first detection is not delayed. `model` is an id, or 'all'. Returns at
once with progress; poll get_model_status. A failed or interrupted download
is resumed by calling this again.
```

**`scan_batch`**

```
Scan up to 200 file paths and/or URLs one after another and return one
summary row each (verdict, document score, flagged sentences, tells, scan_id).
Full results open from the dashboard history. May trigger a model download:
returns status "downloading" at once if the model is not on disk.
```

### Server instructions (sent at initialize)

```
ai-detect scores text for AI authorship on this machine. Text, files and fetched pages never leave it; the only network traffic is model downloads from Hugging Face and the one page a URL tool is asked to fetch.
Models download on first use and are cached: desklib 1736 MB, light 126 MB, gpttrace-150m 151 MB, gpttrace-1b 951 MB, tabularis 598 MB, conpara 1738 MB. The default is desklib. A detect call never waits for a download: if the model is not ready it returns status "downloading" with a percentage and a message. Relay that message to the user and call the tool again in a minute. get_model_status shows progress for any model; prefetch starts a download ahead of time.
Every result carries dashboard_url, a local page with the highlighted text and details. The dashboard is at http://127.0.0.1:8765 unless that port was busy; open_dashboard returns the real address and can open it in the browser.
Scores are evidence, not proof. Report the document score with its confidence and notes; single-sentence scores are a rough signal.
```

### How downloads behave (never a hang)

- A detect, compare or batch call whose model is not on disk starts the download in the background and returns at once with `status: "downloading"`, per-model `bytes_done`, `bytes_total`, `percent`, `eta_seconds`, the `dashboard_url`, and a `message` to relay. Calling again later returns the result.
- `get_model_status` gives the same fields for any model. `status` is `ready`, `downloading`, `absent` or `failed`; `state` says `not_downloaded` instead of `absent`. A failure carries the reason in `error`.
- `prefetch` starts a download ahead of time (`model` id or `all`). Calling it again after a failure resumes: huggingface_hub keeps partial files.
- While a scan runs the server sends MCP progress notifications if the client supplied a `progressToken`. On SDK 1.x it also sends a log notification per stage. On SDK 2.x it does not, because that SDK marks the logging capability deprecated (its warning cites SEP-2577, 28 Jul 2026).
- Verified by test: a real 126 MB download into an empty cache reported rising percentages and an ETA, then `ready`. The download-then-retry flow in the web UI is covered by the browser tests with a simulated download. A real multi-GB download through an MCP client was not run.

### Architecture note for the README

The MCP process is a thin client. Detection runs in a second process, the engine, which is the same local web server `ai-detect serve` starts. The MCP server launches it as a child (or reuses one already running on the default port) and talks to it over HTTP on 127.0.0.1. The engine stops when the MCP process exits. The engine's log is `~/.ai-detect/engine.log`. Reason: on Windows, loading a compiled Python module hangs while another thread is blocked reading standard input, which is what an MCP stdio server does; the 1.0.0 server hung on every detect call in testing for this reason.

## 5. Web UI

Start: `ai-detect serve` (opens the browser), or the MCP tool `open_dashboard`, or it starts by itself the first time an MCP tool runs. Address: `http://127.0.0.1:8765`, or the next free port; `AI_DETECT_PORT` changes the first port tried. Bound to 127.0.0.1 only; requests with any other Host header get 403; cross-site writes are refused. No external requests, no web fonts, no telemetry, no build step: three static files (`ai_detect/web/static/`).

|---|---|

Progress: per-model download bars, then per-model loading/scoring |

## 7. Signals other than the model score

All of these are reported next to the model scores and are never mixed into them.

**Sentence patterns** (`ai_detect/patterns.py`): `missing_contraction`, `formal_verb` (20 verbs, every inflection, -ise and -ize), `formal_transition`, `ai_frame` ("For X who Y"), `ai_slop` (27 words), `vague_abstraction`, `flaggy_adverb`. Each finding has the matched text, a suggestion and character offsets. Also the sentence-length metric (`text_metrics`: mean, standard deviation, coefficient of variation).

**Structure and style tells** (`ai_detect/tells.py`), each with its location, an example quoted from the text, a suggestion and a severity:

| Family | Tells |
|---|---|
| Prose | `em_dash`, `rule_of_three` (only when three-item lists are dense), `three_beat`, `not_x_but_y`, `stock_vocabulary`, `signpost_phrase`, `hedging_tail` (trailing "-ing" clause), `hedge` |
| Sections | `stock_opener`, `definition_opener` (first sentence defines the heading), `tidy_closer`, `conclusion_heading` |
| Headings | `emoji_heading`, `question_heading`, `title_case_heading`, `heading_density` |
| Lists | `bold_lead_bullets`, `emoji_bullets`, `lists_of_three`, `bold_lead_paragraphs`, `bullet_density` |
| Rhythm | `uniform_paragraphs`, `uniform_sentences` |
| FAQ | `faq_restates_body` |

At most 12 instances of one tell are listed; the summary counts all. The rules are generic habits of machine-written copy. A hit proves nothing alone: people write em dashes and three-item lists.

**Visual tells** (`ai_detect/visual.py`, URL and `.html` input only), from the rendered page's geometry and computed styles, each with a rectangle on the screenshot: `gradient_hero`, `centred_hero`, `card_grid_of_three`, `icon_feature_grid`, `uniform_section_rhythm`, `wall_of_bullets`, `icon_bullets`, `ai_image_candidate`, `stock_image_candidate`. The two image tells are flagged only from a file name, alt text or caption and say so; nothing analyses pixels.

**Vision second opinion** (optional, off by default): from the Signals tab the screenshot can be sent to an OpenAI-compatible endpoint the user types in. A non-local address requires ticking a confirmation, because it uploads the screenshot. This code path was not exercised against a real vision model.

**Perplexity and burstiness** (optional, `--perplexity`): GPT-2 (`openai-community/gpt2`, MIT, 548 MB; https://huggingface.co/openai-community/gpt2, read 24 Nov 2026) scores each sentence; the report gives document perplexity, per-sentence values, and burstiness (the spread). A readout with no verdict.

**Document-level score**: sentences are packed into passages of about 200 words (never across a heading) and scored whole, which is how the detectors were trained. `document_ai_pct` is the word-weighted mean.

## 8. URL fetching

One page per call, through Playwright's Chromium with a current desktop Chrome user agent and JavaScript rendered. It follows that URL's own redirects and loads its sub-resources. It does not crawl, click, type, submit forms or sign in; downloads are refused; dialogs are dismissed. Default timeout 30 seconds. The article is taken from `<article>`/`<main>` or the container with the most paragraph text; navigation, headers, footers, sidebars, cookie banners, author boxes and code blocks are dropped; headings, paragraphs, lists, bold lead-ins, tables and captions are kept. A full-page JPEG is saved (clipped at 16,000 px). Without Playwright the error message gives the two install commands.

## 10. Limits and known gaps

- **Single-sentence scores are weak for every model** (sentence AUROC 0.66 to 0.84 in the local evaluation; passages 0.96 to 0.999). The document score is the one to quote.
- Calibration rests on a small corpus (25 human passages, one AI generator). See the evaluation document.
- The paired-sentence figures in `docs/detection-patterns.md` (for example 92.6% against 0.03%) **did not reproduce** with desklib on 24 Nov 2026 (91.9% against 79.7%). That page now carries a notice. Its numbers should not be quoted until re-measured.
- English only. No model here was tested on other languages.
- No GPU run in this work. `--device cuda` is untested for the new models.
- Screenshots in `docs/screenshots/` were taken while the version string still read `2.0.0.dev0`.
- The MCPB bundle was packed and its command run by hand; it was not installed into Claude Desktop.
- Features in code that are documented only here: the `--low-memory` flag; the `tmr`, `gpttrace`, `gpttrace-150`, `gpttrace-v8s` and `modernbert` model aliases; `AI_DETECT_READY_TIMEOUT`; `AI_DETECT_EXTRAS`; the hidden `serve --exit-with-parent` flag used by the MCP server; the `/api/*` HTTP endpoints of the dashboard (listed in `ai_detect/web/app.py`); `scripts/eval_models.py`, `scripts/calibrate_ensemble.py`, `scripts/make_screenshots.py`, `scripts/build_features_doc.py`; the Python API (`from ai_detect import classify_text`, `ai_detect.analyze.analyze`, `load_source`, `compare`).
